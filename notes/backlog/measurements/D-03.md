# D-03 — the fused reduction twins, measured with the coded write in

Status: **measured on the local lane, 2026-11-28, on the head that carries the coded write
(`599d79aa`).** What this run settles, and what it does not, is stated below line by line.

## What changed since the last note

The item's Change line asked for the coded / staged write at 48 rows. It is in:

* `libr4d/r4d_ar_add_rmsnorm.hip` takes `wire` 0 exact, 6 coded. Coded pushes through
  `r4d_ar_arc2.h`'s two-rank slot (16.125 bytes a chunk, lossless): a wave codes one 32-chunk group,
  each row is whole groups, the peer's groups are decoded into dynamic shared a row at a time and
  pass one reads the same bf16 words in the same thread order, so the sum of squares still folds in
  `kR4dSumLanes`' partition and the fold's rounding is untouched.
* The launcher refuses 6 unless the message is whole 256-value waves, the instance is P2P's, and the
  coded image fits the slot; the shape function refuses it at declare time for anything else. Both
  refusals have card-less rows in `tests/r4d_emu/test_ar_add_rmsnorm.cpp`.
* `arch/hyv4flash/hyv4flash_dfly.h` declares `wire` 6 for the twin wherever `E % 256 == 0` (both
  modes), and carries three documented bisect knobs: `RAD_AR_WIRE`, `RAD_D03_MODE0/1`,
  `RAD_AR_CODED_SLOT`.
* `r4d_shape_ar_add_rmsnorm` describes the same rule, and the slot sizing in `r4d_ar_entry.hip`
  already grows a two-rank bf16 slot to hold the coded image.

Tests on the head: `r4d_emu_ar_add_rmsnorm` 0 failure(s) over every mode/width/dtype row (including
the two new refusals), `r4d_fuse_test` 192 checks over 10 cases, `hyv4flash_arch_test` 40,466 checks
over 78 cases.

## The open observation, not attributed to this kernel

Across builds the merge base's fourth greedy text is `9ae27a62` and this head's is `0676d77d`. The
other three texts are identical in every run of both arms. It reproduces with the twins disabled
(`RAD_D03_MODE0=0 RAD_D03_MODE1=0`, 3285 declared ops — the base's own count) and with the coded slot
sizing disabled as well, so it is not the twin's arithmetic, not the coded wire, and not the slot
growth. Same-binary toggles do not move it. That makes it either a difference in the shared code both
builds compile (the head adds files, which can shift a shared kernel's scheduling) or a build-layout
dependent nondeterminism in the engine/drafter at a marginal prompt. It is recorded here as an open
observation with the controls that bound it; the next probe is a graph-level chain-vs-twin oracle at
the exact served shape on one build, which is what r4d_selftest / rad-kbench is for.

Caveats: stock clang 21.1.8 with `RAD_HIP_VOPD_REPEATABLE=OFF`, the local lane rather than iks, no
container, disk n-gram, author-run. The commit after this note is the code head.
